# config —— NVS 里的配置与校准数据

## 职责

把掉电不能丢的东西存住：

- 十二颗 IMU 的陀螺零偏
- 磁力计椭球拟合的九个系数
- 手别（左手还是右手）
- 校准时间戳与数据版本

不负责怎么算这些数据，只负责存和取。

## 依赖

- ESP-IDF 的 `nvs_flash`
- 无其它模块依赖

## 对外接口

```c
esp_err_t cfg_init(void);

// 手别
uint8_t cfg_get_hand(void);            // 0 = 右手，1 = 左手
esp_err_t cfg_set_hand(uint8_t hand);

// 陀螺零偏，每颗三个分量
esp_err_t cfg_get_gyro_bias(uint8_t idx, float out[3]);
esp_err_t cfg_set_gyro_bias(uint8_t idx, const float in[3]);

// 磁力计椭球系数
esp_err_t cfg_get_mag_cal(float coef[9]);
esp_err_t cfg_set_mag_cal(const float coef[9]);

// 整块读写，校准流程结束时调一次
esp_err_t cfg_save_all(void);
esp_err_t cfg_erase_all(void);
```

写接口只改内存副本，`cfg_save_all` 才落盘。校准流程中途崩溃不会留下半套数据。

## 验收（P0）

- 写入后断电重启，读回的值和写入一致
- 首次上电没有存过数据时，读接口返回默认值（零偏全零、手别右手）而不是报错
- 结构体版本号变化时自动清空旧数据

第三条是为了以后改结构时不读到垃圾。

## 当前实现架构（尚未实现）

### 简介

一个命名空间，几个固定键，结构体带版本号。全部用 `nvs_set_blob` 存，读的时候先查版本，对不上就当没存过。

### 存储布局

| 键 | 类型 | 内容 |
|---|---|---|
| `hand` | uint8 | 0 右手，1 左手 |
| `magcal` | blob | 九个 float，椭球系数 |
| `bias` | blob | 12 × 3 个 float，陀螺零偏 |
| `ver` | uint32 | 结构版本号 |
| `calts` | uint32 | 上次校准时的开机毫秒数 |

命名空间用 `eicfg`。

### 版本号

当前版本取 1。每次 `cfg_init` 先读 `ver`，不等于当前版本就把整个命名空间清空，全部回到默认值。

加这个字段是因为零偏和椭球系数的长度、含义以后可能变。没有版本号的话，改结构后旧数据会被当成新格式读，算出来的姿态会莫名其妙地偏。

### 默认值

| 项 | 默认 |
|---|---|
| 手别 | 右手 |
| 零偏 | 全零 |
| 椭球系数 | 单位阵，即不做校正 |

零偏全零意味着第一次用之前必须跑一次校准，否则姿态会随温漂慢慢歪。这是设计上接受的，校准流程会强制走一遍。

### 写入时机

只在两个时刻落盘：校准流程结束、用户通过 CLI 改手别。

运行中不改 NVS。NVS 写入涉及擦除，会阻塞几十毫秒，放在 200Hz 的循环里会把节拍打乱。

### 掉电保护

`cfg_save_all` 依次写三个 blob，中间断电会留下部分旧值。

不打算做事务保护——校准数据重算一次只要十几秒，比写一套日志式存储划算。版本号能保证读到的是完整的一套，读不全就当作没存过。

### 容量

一个 blob 最大 1984 字节。零偏那块 12 × 3 × 4 = 144 字节，椭球 36 字节，远低于上限。
