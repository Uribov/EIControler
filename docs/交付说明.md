# 交付说明

一晚上的成果，全部是能在这台电脑上验证完的部分。需要板子的都列在最后一节。

## 做完了什么

| 模块 | 文件 | 行数 |
|---|---|---|
| 板级 | `src/board/` | 约 190 |
| IMU 驱动 | `src/drivers/qmi8658a.c` | 265 |
| 磁力计驱动 | `src/drivers/qmc5883p.c` | 约 110 |
| 算法层 | `src/lib/`（四元数、VQF、帧打包） | 约 380 |
| 采样调度 | `src/sample/` | 约 200 |

合计约 2100 行，编译通过，Flash 占用 9.6%，RAM 4.7%。

## 怎么验证的

一条命令跑完全部：

```bash
bash tools/verify.sh
```

它会依次做五件事：

1. 编译固件
2. PC 端跑姿态滤波的五个场景测试
3. PC 端用 C 打一个 210 字节的帧
4. 用 Python 解析这个帧，和 C 端结果对拍
5. 跑协议自检，包括 CRC 抓错和日志噪声环境下的流式同步

实测结果全部通过。

姿态算法的五个场景是：静止保持、绕轴积分精度、初始倾角收敛、陀螺零偏估计、航向清零。

## 关键技术决定

| 项 | 选择 | 原因 |
|---|---|---|
| 采样率 | 896.8 Hz | QMI8658A 没有 800Hz 档，这是最近的 |
| 姿态算法 | VQF 精简实现 | 公开评测里调参外精度最高的一档 |
| 手掌 | U13/U14 加权融合 | 降噪 29%，零偏方差减半 |
| 手指 | 十颗各自 6D，输出相对手掌 | 不依赖磁，省算力 |
| 帧长 | 210 字节，200 帧每秒 | 42kB/s，USB 占 3% |
| 平台 | espressif32 6.12.0 + IDF 5.x | 新平台在 PIO 下缺构建产物，退回这档 |

## 没做的（需要板子）

| 项 | 为什么 |
|---|---|
| 上板读 IMU | 没有硬件 |
| 磁力计椭球标定 | 需要实际转动手腕采数据 |
| 手感调参 | 抖动与延迟的平衡只能实测 |
| 帧率压力测试 | 需要看真实 USB 吞吐 |
| U14 的角色 | 目前和 U13 一起做融合，是否需要独立用途待定 |

另外，`docs/fusion.md` 里描述的磁力计椭球标定流程（`MAG_CALIB` 状态）目前只有接口预留，没有实现。当前磁力计只做航向参考的建立与干扰降权，不做椭球拟合。

## 烧录

```bash
pio run -t upload
```

首次建议先整片擦除：

```bash
pio run -t erase && pio run -t upload
```

## 上位机

```bash
python3 tools/eic_frame.py --dump <串口转存的文件>
```

串口里日志文本会和二进制帧混在一起，解析工具已经做了帧头扫描与 CRC 校验，能自动跳过日志。

## 已知风险

1. **USB Serial/JTAG 与日志同口**。如果上位机不做流式同步，会被日志文本带偏。工具里已经处理，但自写上位的程序要注意。
2. **零偏增益**。运动中的零偏更新系数调得很小（时间常数约 220 秒），是为了不让真实转动被当成零偏吃掉。温漂大会跟得慢一些，需要实测判断。
3. **第一次上电必须做一次零偏校准**，否则姿态会慢慢歪。默认零偏是全零。
