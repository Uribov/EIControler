# VaM 接入协议

手套 → 上位机 → UDP → VaM 插件。本文只定义上位机与插件之间的那一段。

## 为什么要单独定一层

上位机在 Linux 上开发调试，插件在 Windows 的 VaM 里跑。两边分开写、分开测，中间靠这个协议对接，谁也不等谁。

## 数据流

```
手套 ──USB──> eic_bridge.py ──UDP 127.0.0.1:9001──> VaM 插件
               解算骨骼                            应用骨骼
```

上位机负责把 12 个 IMU 的相对姿态翻译成 16 个手部关节的旋转，插件只负责照着设。

## UDP 包格式

定长 272 字节，小端：

| 字段 | 长度 | 说明 |
|---|---|---|
| 魔数 | 4 | ASCII `EIGV` |
| 版本 | 2 | 当前 1 |
| 手别 | 1 | 0 右手，1 左手 |
| 保留 | 1 | 0 |
| 序号 | 4 | 每包加一 |
| 时间戳 | 4 | 毫秒，上位机本地时钟 |
| 关节 | 256 | 16 × 4 个 float32 四元数 |

每个四元数顺序 `[w, x, y, z]`，表示该关节相对父关节的旋转。

## 关节顺序

固定 16 个，下标即包内偏移：

| 下标 | 关节 | 来源 |
|---|---|---|
| 0 | hand | 手掌绝对姿态 |
| 1 | thumb1 | 大拇指近节相对手掌 |
| 2 | thumb2 | 大拇指中节相对近节 |
| 3 | thumb3 | 大拇指远节，推算 |
| 4 | index1 | 食指近节 |
| 5 | index2 | 食指中节 |
| 6 | index3 | 食指远节，推算 |
| 7 | middle1 | 中指近节 |
| 8 | middle2 | 中指中节 |
| 9 | middle3 | 中指远节，推算 |
| 10 | ring1 | 无名指近节 |
| 11 | ring2 | 无名指中节 |
| 12 | ring3 | 无名指远节，推算 |
| 13 | pinky1 | 小指近节 |
| 14 | pinky2 | 小指中节 |
| 15 | pinky3 | 小指远节，推算 |

远节按 `远节 = 中节 × 0.66` 推算，这是人体 DIP 与 PIP 的联动比例。

## 手指与 IMU 的对应

手套固件输出的相对四元数按片选排列，上位机负责映射成手指：

| 手指 | 近节 IMU | 中节 IMU |
|---|---|---|
| 小指 | CS1 | CS2 |
| 无名指 | CS3 | CS4 |
| 中指 | CS5 | CS6 |
| 食指 | CS7 | CS8 |
| 大拇指 | CS9 | CS10 |

这是右手版的排列。左手版反序，见 `docs/fusion.md`。

## 坐标系

关节旋转沿用固件的机体系，上位机不做额外变换：

- x+ 指向肘部
- y+ 指向身体右侧
- z+ 指向天空

这套轴直接来自 QMI8658A 的原生坐标系，选它是为了让 z+ 与重力反方向一致，姿态滤波的初始条件天然成立。

VaM 的骨骼朝向是它自己的约定，插件里用 `_mountOffset` 补这个差，上位机不管。

## 频率

上位机每 5ms 发一包，200Hz。插件端只取最新一包，不做队列堆积。

丢包不补发。序号跳变时插件应当无视，直接用新数据。
