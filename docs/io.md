# io —— 帧打包与 USB 发送

## 职责

把 `fusion` 算好的姿态变成一根字节流送出去：

- 按固定布局打包成帧
- 计算校验
- 通过 USB 虚拟串口发出去
- 发送失败时计数，不阻塞上游

这一层不碰姿态计算，也不管数据对不对。它只保证「进来什么、出去什么，一个字节不差」。

## 依赖

- `fusion`：`fusion_get_frame()` 取姿态与温度
- `lib/frame_codec`：打包与 CRC，纯 C，PC 端测试共用同一份代码
- USB Serial/JTAG 驱动：ESP-IDF 内置，不需要额外组件

## 对外接口

```c
// 建 USB 接口、起发送任务
esp_err_t io_start(void);

// 取一帧打包好的数据，调试用
size_t io_build_frame(uint8_t *buf, size_t cap);

// 统计
io_stats_t io_get_stats(void);
```

`io_start` 之后由内部任务自己按 200Hz 节奏取数据、打包、发送，外部不用驱。

## 验收（P0）

- 上位机能连续收到 200 帧每秒，序号连续，CRC 全对
- 拔掉 USB 后不崩溃，重插能自动恢复发送
- 发送队列满时丢帧计数增加，其余部分不受影响
- 上位机解析出的四元数能还原出正确的姿态，单位四元数模长误差小于 1e-3

第一条是基本盘，第二条是现场最容易出问题的地方。

## 当前实现架构（尚未实现）

### 简介

一个任务每 5ms 取一次姿态、拼成 210 字节、写给 USB。写不进去就丢掉这一帧并计数，绝不等待。

### 帧布局

| 字段 | 长度 | 类型 | 说明 |
|---|---|---|---|
| 帧头 | 2 | 固定 | `0xAA 0x55` |
| 序号 | 2 | uint16 小端 | 每帧加一，回绕 |
| 时间戳 | 4 | uint32 小端 | 毫秒，来自 `esp_timer` |
| 手掌四元数 | 16 | float32 × 4 | 顺序 `w, x, y, z` |
| 相对四元数 | 160 | float32 × 40 | 十颗手指依次排列，每颗四个分量 |
| 温度 | 24 | int16 × 12 | 单位 0.01 摄氏度 |
| CRC | 2 | uint16 小端 | CRC16-CCITT，覆盖前面全部 |

整帧 210 字节，200 帧每秒即 42kB/s。

USB 全速链路 1.5MB/s，占用不到 3%。

### 日志与帧混在同一个口上

用的是 USB Serial/JTAG，`ESP_LOGI` 的输出和二进制帧走同一个端点。所以上位机收到的是帧与文本交错的字节流，中间夹着 `I (1234) main: ...` 这样的文本。

上位机必须按流处理，不能假设每个字节都属于帧：

1. 扫描 `0xAA 0x55`
2. 命中后试着解析 210 字节
3. CRC 不过就往前挪一个字节重来
4. CRC 过了才采信

`tools/eic_frame.py` 里的 `parse_stream()` 就是这个逻辑，日志文本会被自然跳过。

### 字节序

全部小端。S3 本身就是小端，直接按内存布局 `memcpy` 即可，不需要逐字节拼。

浮点按 IEEE 754 单精度原样传，上位机按同样的格式解析。

### CRC

用 CRC16-CCITT-FALSE：初值 `0xFFFF`，多项式 `0x1021`，不做输入输出反转。

选它是因为实现简单、查表小、在嵌入式里到处都是现成代码，上位机用任何一种语言都能找到对应实现。

### 温度

`fusion` 给的是摄氏浮点，打包时乘以 100 取整成 int16，范围 ±327 摄氏度，够用。

上位机除回去就是摄氏度。

### 发送策略

发送任务优先级 10，和 `fusion` 同级，绑 core0。

每帧的流程：

| 步骤 | 动作 |
|---|---|
| 1 | 等 5ms 节拍 |
| 2 | 从 `fusion` 取最新一帧数据 |
| 3 | 拼 210 字节 |
| 4 | 写 USB，写不进去就丢帧并计数 |

第 4 步不重试。USB 慢一拍就丢，等它反而会堆积延迟，跟这套系统的目标相反。

### USB 连接状态

启动时 USB 可能还没枚举完，这时候写会返回错误。处理方式是：

- 未连接时照常打包，只是不写
- 检测到连接后从当前序号继续
- 断开时把队列清空，避免重连后发一堆过期帧

上位机侧收到序号跳变就知道中间断了。

### 序号回绕

uint16 到 65535 后回到 0。上位机判断丢帧用「差值为 1 则连续，否则丢（差值 - 1）帧」，回绕时用模运算，不做特殊处理。

### 为什么不压缩

210 字节里 176 字节是浮点四元数。量化成 int16 能压到 106 字节，省一半带宽。

但现在的带宽占用只有 3%，压不压没区别，而量化会引入舍入误差和一套额外的定点约定。等无线方案上来了再说。
