# EI Controller 固件架构

体感手套主控固件。12 颗 IMU 分时挂在一根 SPI 上，片上完成姿态解算，把四元数打包发给上位机。

## 0. 简介

这套固件干三件事：按固定节拍把 12 颗 IMU 的数据读出来、在片上算成姿态、打包从 USB 发出去。

难点不在解算，在采样时序。12 颗 IMU 共用 SCK、MOSI、MISO 三根线，靠 74HC154 译码器分时选通。任何一颗读慢了 FIFO 会溢出丢样本，读得太密 CPU 又被占满。

目标总延迟 10ms，按当前设计估算落在 7ms 左右。


---

## 1. 硬件约束

| 部件 | 型号 | 数量 | 说明 |
|---|---|---|---|
| 主控 | ESP32-S3 SuperMini | 1 | 双核 240MHz，4MB Flash / 2MB PSRAM |
| IMU | QMI8658A | 12 | 位号 U3–U14，SPI，最高 15MHz |
| 磁力计 | QMC5883P | 1 | 位号 U15，I2C |
| 译码器 | 74HC154 | 1 | 4 线转 16 路 |

引脚分配以原理图为准：

| 信号 | GPIO | 网络名 |
|---|---|---|
| SCK | 13 | SCK_E |
| MOSI | 12 | MOSI_E |
| MISO | 11 | MISO |
| A0 | 8 | A0 |
| A1 | 9 | A1 |
| A2 | 10 | A2 |
| A3 | 5 | A3 |
| CS_E | 4 | CS_E |
| SDA | 7 | SDA |
| SCL | 6 | SCL |

74HC154 的 E0 接地常开，E1 接 CS_E 作总使能。Y0–Y11 依次接 CS1–CS12，对应 12 颗 IMU，Y12–Y15 空置。

十二路片选用掉十六路里的十二路，剩下四路留给以后扩展。

## 2. 分层

| 层 | 目录 | 职责 | 约束 |
|---|---|---|---|
| L0 | `board/` | SPI、I2C 总线初始化，引脚定义 | 引脚只出现在 `pinmap.h`，换板只改一处 |
| L1 | `drivers/` | QMI8658A、QMC5883P、74HC154 的寄存器级操作 | 不含业务逻辑，换器件只换这一层 |
| L2 | `sample/` | 扫描调度、时间戳、环形缓冲 | 全系统的时序中心 |
| L3 | `fusion/` | 零偏校准、VQF 姿态解算 | 纯数学，可脱离硬件在 PC 上验证 |
| L4 | `io/` | 帧打包、USB 发送、CLI | 只认 L3 的输出结构体，不碰寄存器 |

分层的目的不是好看，是让问题能定位。姿态不对先怀疑 L3，数据错乱先怀疑 L2，连不上先怀疑 L0。每层只允许调用下一层，反过来走就要重划。

## 3. 任务与数据流

```
        esp_timer 5ms 周期中断
                 │ 只发通知，不干活
                 ▼
    ┌────────────────────────────┐
    │ T1 sample   core1  优先级18 │
    │ 逐颗选通 → 读 FIFO → 打戳   │
    └──────────────┬─────────────┘
                   │ 原始帧环形缓冲
                   ▼
    ┌────────────────────────────┐
    │ T2 fusion   core0  优先级10 │
    └──────────────┬─────────────┘
                   │ 姿态帧环形缓冲
                   ▼
    ┌────────────────────────────┐
    │ T3 tx       core0  优先级10 │
    └────────────────────────────┘

    旁路：T4 mag  优先级5   10ms 一次读磁力计
          T5 cli  优先级3   事件驱动
```

| 任务 | 优先级 | 核 | 周期 |
|---|---|---|---|
| T1 sample | 18 | core1 | 5ms |
| T2 fusion | 10 | core0 | 被 T1 唤醒 |
| T3 tx | 10 | core0 | 被 T2 唤醒 |
| T4 mag | 5 | core0 | 10ms |
| T5 cli | 3 | core0 | 事件驱动 |

T1 独占 core1，因为 5ms 内要完成 12 次 SPI 事务。被 WiFi 栈抢占一次就可能让 FIFO 溢出，而丢样本不会报错，只表现为姿态偶尔抖一下。

## 4. 时序预算

| 环节 | 延迟 |
|---|---|
| FIFO 攒样本 | 平均 2.5ms |
| 解算 | 小于 0.5ms |
| USB 传输 | 1ms |
| 上位机解析 | 2–3ms |
| 合计 | 约 7ms |

采样率 896.8Hz 时有线链路每 5ms 刷一帧，一帧里每颗 IMU 贡献 4 到 5 个样本。

FIFO 里的样本数会浮动。12 颗 IMU 各有独立晶振，采样相位与主控定时器对不齐，某次读到 1 个、某次读到 3 个都正常。代码不能假定每次恰好 4 个，必须先读水位寄存器按实际数量取。

## 5. 姿态解算

用 VQF 的机制，自己写精简实现，不直接引第三方库。

| 部位 | 数量 | 模式 | 原因 |
|---|---|---|---|
| 手掌 | 1 | 9D（含磁力计） | 没有外部光学参考，绝对航向只能靠磁 |
| 手指 | 11 | 6D | 只输出相对手掌的姿态，不需要绝对航向 |

选 VQF 是因为它在公开数据集上的调参外精度明显高于 Madgwick 和 Mahony：同参数下平均 RMSE 2.08 度，另外两个分别是 5.08 度和 7.49 度。代价是单次更新约 4400 个周期，11 个实例跑 896.8Hz 约占单核 18%，在预算内。

实现上保留三个机制，去掉用不到的部分：

| 保留 | 去掉 |
|---|---|
| 加速度在近惯性系滤波 | 离线后处理模式 |
| 陀螺零偏在线估计 | 任意组合的多采样率支持 |
| 磁干扰检测与降权 | 全部可调参数的对外接口 |

代码量约 350–450 行，不依赖 CMSIS-DSP。

磁干扰抑制这段不能省。手边有手机、金属桌面、扬声器时磁力计读数会被拉偏，没有降权机制航向会直接跟着跳。

## 6. 帧格式

```
[2B 帧头] [2B 序号] [4B 时间戳] [16B 手掌四元数] [10 × 16B 相对四元数] [12 × 2B 温度] [2B CRC]
```

帧长 210 字节，5ms 一帧即 200 帧每秒，占用约 42kB/s。USB 全速链路带宽 1.5MB/s，余量充足。

时间戳用 32 位毫秒，从 `esp_timer` 换算，可连续跑 49 天不回绕。序号用于判断丢帧，相邻两帧相差超过 1 就说明中间掉了。

温度是 12 颗 IMU 各自的片内温度，各占 2 字节有符号。温漂变化慢，不必每帧重新读，1 秒读一次缓存起来、每帧带上当前值即可，这样不增加 SPI 事务。

四元数先用单精度浮点传。以后带宽紧张再量化成 int16，四元数部分能从 176 字节压到 88 字节。

## 7. 校准流程

`fusion/` 内一个状态机，四个状态：

```
IDLE ──(静止 1s)──► GYRO_BIAS ──► YAW_ZERO ──► RUNNING
                                              │
        (首次使用或长按) ──► MAG_CALIB ───────┘
```

| 时机 | 动作 | 时长 | 作用 |
|---|---|---|---|
| 首次使用、换环境 | 手腕绕八字转几圈 | 约 15 秒 | 标定磁力计的硬铁、软铁偏差 |
| 每次戴上 | 手掌朝前静止 | 1 秒 | 陀螺零偏，同时把当前朝向记成「正前方」 |
| 使用中 | 无需动作 | 无 | VQF 自动跟零偏、自动抗磁干扰 |

绕八字转这一圈能校出陀螺的尺度因子，这是静止永远校不出来的：读数偏 1%，转一整圈航向就错 3.6 度。

校准结果存 NVS，掉电不丢。标定磁力计要在没有明显干扰的地方做，站在铁桌子旁标出来的底值会把桌子的干扰一起算进去。

## 8. 决策点

| 编号 | 决策 | 取值 |
|---|---|---|
| **D1** | 采样率 | 有线 896.8Hz，蓝牙模式 448.4Hz |
| **D2** | 读取方式 | FIFO 批读 |
| **D3** | 时间戳 | 统一取 esp_timer |
| **D4** | 解算位置 | 片端完整解算，只传四元数 |
| **D5** | 传输 | 先用 USB CDC |
| **D6** | 帧格式 | 自定义二进制 |
| **D7** | 总延迟目标 | 10ms |
| **D8** | 磁力计 | 手掌那颗 9D，手指全部 6D |
| **D9** | 手指算法 | 先全上 VQF，CPU 吃紧再降级 |
| **D10** | 航向初值 | 开机姿势，不朝北 |
| **D11** | 校准交互 | 首次绕八字，之后每次静止 1 秒 |
| **D12** | 校准数据 | 存 NVS |
| **D13** | 时间戳宽度 | 32 位毫秒，49 天不回绕 |
| **D14** | 帧内容 | 含 12 颗 IMU 片内温度，1Hz 刷新 |

批读窗口定在 5ms：896.8Hz 下每颗每次约 4.5 个样本，落在 4 到 5 之间浮动。更短的窗口能再降延迟，但占用上升明显，10ms 的总目标用不上。
