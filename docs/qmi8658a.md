# qmi8658a —— QMI8658A 的寄存器驱动

## 职责

管好一颗 QMI8658A 的所有寄存器操作：

- 上电初始化：复位、配置 SPI 模式、设量程与 ODR、打开 FIFO
- 按需读回 FIFO 里的样本
- 读片内温度
- 出错时能判断是通信坏了还是芯片没配好

十二颗 IMU 共用这一份驱动，靠片选区分。驱动本身不认识「第几颗」，只认「操作哪一路片选」。

## 依赖

- `board`：SPI 总线句柄、74HC154 的片选接口、GPIO 控制
- 不依赖 `sample` 和 `fusion`，驱动不关心数据拿去干什么

驱动是纯寄存器层。数据怎么攒、怎么算、怎么发，都不在这一层。

## 对外接口

```c
// 初始化一颗：复位 → 校验 WHO_AM_I → 配置 → 开 FIFO
esp_err_t qmi_init(uint8_t cs_index);

// 读 FIFO 里现有样本数（个），0 表示没有新数据
esp_err_t qmi_fifo_level(uint8_t cs_index, uint8_t *count);

// 读一批样本，每样本 12 字节（加速度 6 + 陀螺 6）
esp_err_t qmi_fifo_read(uint8_t cs_index, uint8_t *buf, uint8_t max_samples, uint8_t *got);

// 读温度，返回摄氏度
esp_err_t qmi_read_temp(uint8_t cs_index, float *temp_c);

// 单寄存器读写，调试用
esp_err_t qmi_read_reg(uint8_t cs_index, uint8_t reg, uint8_t *val);
esp_err_t qmi_write_reg(uint8_t cs_index, uint8_t reg, uint8_t val);
```

片选索引用 `0..11`，对应 CS1..CS12，由 `board` 层翻译成 74HC154 的地址线。

## 验收（P0）

- 十二颗逐颗读 `WHO_AM_I`，全部返回 `0x05`
- 打开 FIFO 后连续读 100 轮，样本数累计误差小于 1%，不出现负增长
- 温度读数在室温下落在 20 到 40 摄氏度之间，同一时刻十二颗互相相差不超过 10 度
- 拔掉某颗的片选，驱动能返回错误而不是卡死

第一条过了说明 SPI 时序和地址自增都对，后面才有意义。

## 当前实现架构（尚未实现）

### 简介

一颗 QMI8658A 有 23 个 UI 寄存器，驱动只碰其中十来个。难点不在寄存器数量，在 FIFO：读模式一开，新数据就不再进 FIFO，必须在下一个采样周期到来前读完退出。

### 寄存器表

| 名称 | 地址 | 用途 |
|---|---|---|
| WHO_AM_I | 0x00 | 固定 `0x05`，用来确认通信 |
| CTRL1 | 0x02 | SPI 模式、地址自增、字节序 |
| CTRL2 | 0x03 | 加速度量程与 ODR |
| CTRL3 | 0x04 | 陀螺量程与 ODR |
| CTRL5 | 0x06 | 低通滤波 |
| CTRL7 | 0x08 | 传感器使能 |
| CTRL9 | 0x0A | 命令通道 |
| FIFO_WTM_TH | 0x13 | 水位阈值 |
| FIFO_CTRL | 0x14 | FIFO 模式与读模式位 |
| FIFO_SMPL_CNT | 0x15 | 当前样本数 |
| FIFO_STATUS | 0x16 | 满/水位/非空标志 |
| FIFO_DATA | 0x17 | FIFO 出口 |
| STATUSINT | 0x2D | 第 7 位是 CTRL9 完成标志 |
| TEMP_L / TEMP_H | 0x33 / 0x34 | 片内温度 |
| AX_L 到 GZ_H | 0x35 到 0x40 | 加速度与陀螺的直读出口 |

数据寄存器是 16 位补码，低字节在前。

### SPI 事务

读命令把地址最高位置 1，写命令最高位保持 0：

```
读：0x80 | reg
写：reg
```

一次事务里 CS 全程拉低。多字节读靠 CTRL1 的地址自增位，地址会自动往后走。

CTRL1 配 `0x40`：4 线 SPI，地址自增打开，小端字节序。小端是为了读出来的字节顺序和寄存器表一致，省掉手工拼字节。

SPI 速率 15MHz，模式 0。S3 的 SPI 主机默认就是模式 0，不用改。

### 初始化序列

每颗 IMU 上电后走一遍：

| 步骤 | 操作 |
|---|---|
| 1 | 写 CTRL1 = 0x80 软复位，等 15ms |
| 2 | 读 WHO_AM_I，不等于 0x05 就报错退出 |
| 3 | 写 CTRL1 = 0x40，配 SPI 模式 |
| 4 | 写 CTRL2，设加速度量程与 ODR |
| 5 | 写 CTRL3，设陀螺量程与 ODR |
| 6 | 写 CTRL5，开低通滤波 |
| 7 | 写 CTRL7，同时使能加速度与陀螺 |
| 8 | 写 FIFO_WTM_TH 和 FIFO_CTRL，开 FIFO 模式 |

第 2 步是整条链路的体检点。WHO_AM_I 读不对，后面所有配置都是白写。

### FIFO 读取流程

按数据手册 8.8 节的五步走：

1. 读 FIFO_STATUS（0x16），看非空标志
2. 读 FIFO_SMPL_CNT（0x15）拿到样本数
3. 写 CTRL9 = 0x05，请求 FIFO 读模式
4. 轮询 STATUSINT（0x2D）第 7 位，等命令完成
5. burst 读 FIFO_DATA（0x17），读 `样本数 × 12` 字节

读完之后把 FIFO_CTRL 的读模式位清零，FIFO 恢复写入。

第 3 和第 4 步是 CTRL9 协议，每次读都要走一遍。这是固定开销，样本数越少摊得越薄。

### 读模式期间会丢数据

数据手册明确写了：FIFO 读模式一旦打开，新样本不再写入，直接丢弃。必须在下一个采样周期到来前读完并退出。

当前 ODR 下这个窗口约 1.1ms。单颗的读取动作（命令加 60 字节传输）耗时在 60µs 量级，一次读一颗不会撞上。

但十二颗串行读的总耗时约 720µs，接近一个周期。所以绝不能同时打开多颗的读模式，必须逐颗进入、读完退出。这条在 `sample` 层的调度里落实，驱动层只保证单颗操作的原子性。

### 量程与 ODR

| 参数 | 取值 | 说明 |
|---|---|---|
| 陀螺量程 | ±1024 dps | 手指快甩可达 500 到 1000 度每秒，256 不够 |
| 加速度量程 | ±8 g | 手部冲击一般不超过 4g，留一倍余量 |
| ODR | 896.8 Hz | 见下 |

QMI8658A 的 ODR 档位是固定序列，没有 800Hz 这一档。最接近的是 896.8Hz 和 448.4Hz，取前者。

实际采样率比原计划的 800Hz 高 12%，带宽和 CPU 占用相应上浮一点，其余设计不变。
