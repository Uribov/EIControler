# 未来目标

当前不做，但方向定下来的事。写在这是为了防止以后重新想一遍。

## 虚拟 HMD（没有头显也能跑 SteamVR）

### 动机

没有 VR 头显时，SteamVR 起不来，VR 游戏没法测。思路是自己造一个"假头显"：

- 用 ESP32 + IMU 做头部追踪，提供姿态
- 画面渲染到显示器窗口
- SteamVR 认为存在一个 HMD，游戏正常启动

### 架构

```
ESP32 + IMU ──USB──> 虚拟 HMD 驱动 ──> SteamVR
                        │
                        └── IVRVirtualDisplay 拿到合成后的画面
                                  │
                                  ▼
                             显示器窗口
```

驱动要干两件事：提供 HMD 位姿，以及把 SteamVR 渲染完的纹理显示出来。

### 关键项目

| 项目 | 用途 |
|---|---|
| [ValveSoftware/virtual_display](https://github.com/ValveSoftware/virtual_display) | 官方 `IVRVirtualDisplay` 示例驱动，显示链路的底座 |
| [UnoReality](https://github.com/AhmadAlShudeifat/UnoReality) | 开源项目，ESP32-P4 做 SteamVR 头显，思路最接近 |
| [IMU-VR-Full-Body-Tracker](https://github.com/m9cd0n9ld/IMU-VR-Full-Body-Tracker) | ESP32 + BNO080 喂位姿给 SteamVR，证明追踪源可行 |

### 难点

| 问题 | 说明 |
|---|---|
| 单目 | 显示器只有一个画面，没有立体视觉。能转头，没有深度感 |
| Linux 纹理路径 | 官方示例走 Windows DXGI 共享纹理，SteamVR 的 Linux 版用 GL/Vulkan，需要重写 |
| 工作量 | 比手套驱动大一个量级，要接管显示链路、投影矩阵、畸变、分辨率协商 |

### 什么时候做

等 VaM 适配验证完，确认要往 SteamVR 走的时候。如果只是想验证手套，这条路性价比不高——VaM 桌面模式能覆盖同样的事。

## SteamVR Skeletal Input 驱动

把手套做成通用 SteamVR 设备，所有支持 Skeletal Input 的游戏都能用。

现在走的是 VaM 插件路线，两者不冲突：插件验证手感，驱动面向通用。

关键参考：[SteamVR Skeletal Input 文档](https://github.com/ValveSoftware/openvr/wiki/SteamVR-Skeletal-Input)、[VRChat 驱动指南](https://creators.vrchat.com/platforms/pc/steamvr-drivers/)。

## 手机当 HMD

如果只是想低成本玩 VR 游戏，用手机加 Cardboard 盒子配 iVRy 这类软件，比自造虚拟 HMD 省事得多。这条路不涉及我们自己的硬件。
