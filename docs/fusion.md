# fusion —— 12 颗 IMU 的姿态解算与校准

## 职责

把 `sample` 层送来的原始样本变成可直接使用的姿态：

- 每颗 IMU 独立跑一次姿态更新，手背两颗融合成手掌姿态并接磁力计做 9D，手指十颗走 6D
- 手背两颗 IMU 加权融合，降噪并互相校验
- 在线估计陀螺零偏，省掉产线标定
- 检测磁干扰并降低磁权重，避免手靠近金属时航向跳变
- 维护校准状态机，处理零偏、航向零点、磁力计椭球三件事

输出 1 个手掌绝对四元数加 10 个手指 IMU 相对手掌的四元数。相对姿态在片上算好，上位机拿到直接能用。

## 索引映射

十颗手指 IMU 两两一对，每指近节与中节各一颗；手背两颗单独挂着，磁力计 U15 也在手背。

| 片选 | 位号 | 右手 | 左手 |
|---|---|---|---|
| CS1 | U3 | 小拇指 近节 | 大拇指 近节 |
| CS2 | U4 | 小拇指 中节 | 大拇指 中节 |
| CS3 | U5 | 无名指 近节 | 食指 近节 |
| CS4 | U6 | 无名指 中节 | 食指 中节 |
| CS5 | U7 | 中指 近节 | 中指 近节 |
| CS6 | U8 | 中指 中节 | 中指 中节 |
| CS7 | U9 | 食指 近节 | 无名指 近节 |
| CS8 | U10 | 食指 中节 | 无名指 中节 |
| CS9 | U11 | 大拇指 近节 | 小拇指 近节 |
| CS10 | U12 | 大拇指 中节 | 小拇指 中节 |
| CS11 | U13 | 手背，融合对右 | 同右 |
| CS12 | U14 | 手背，融合对左 | 同右 |

手背两颗是一对融合配置，不承担独立的手指语义。U14 在左、U13 在右，沿 y 轴相隔 10mm。

左右手的编号顺序相反：右手从小拇指数到大拇指，左手反过来。固件按手别选映射表，手指姿态的语义由这张表决定。

两只手共用同一块板，板面始终朝手背，装到另一只手上只是位置平移，不翻转。所以 IMU 的机体坐标系相对手指方向两只手一致，解算不需要任何坐标变换，切换映射表就够了。

片选到索引是严格顺序对应，`fusion_get` 的 idx 就是 CS 编号减一。

近节在中节之前这一条是按位号顺序推的，上板时核对一次。

## 依赖

- `sample`：原始样本批（每颗 IMU 的陀螺、加速度、时间戳）
- `board`：无直接依赖，不碰 SPI 和 I2C
- NVS：读写校准结果
- `io`：只通过 `fusion_get()` 被调用，本模块不主动发送

依赖是单向的：`fusion` 不回调 `sample`，也不直接写 USB。

## 对外接口

```c
// 初始化，加载 NVS 里的校准数据
void fusion_init(void);

// 处理一批原始样本。每颗 IMU 约 4 到 5 个，时间步长按批间时间戳差算
void fusion_process_batch(const raw_batch_t *batch);

// 取某颗 IMU 的姿态。idx 0..11 对应 CS1..CS12
bool fusion_get(uint8_t idx, float q[4], float *temp_c);

// 取手掌绝对姿态与 10 个相对四元数，供 io 层打包
void fusion_get_frame(fusion_frame_t *out);

// 校准控制
void fusion_calib_begin(calib_mode_t mode);   // 进入零偏/磁标定
calib_state_t fusion_calib_state(void);
```

四元数顺序固定为 `[w, x, y, z]`，表示从机体系到世界系的旋转。所有角度用弧度，温度用摄氏度。

接口里没有「单个样本」的入口。采样天然成批，按批处理能少一次任务切换，也方便时间戳对齐。

## 验收（P0）

- 静止放置 1 秒后零偏估计生效，连续运行 10 分钟航向漂移不超过 2 度
- 绕八字转一圈完成磁力计标定，椭球拟合残差小于 5%
- 11 个实例跑 896.8Hz，`fusion` 部分 CPU 占用低于 25%
- 手靠近金属柜、手机、显示器时航向不出现超过 5 度的跳变

四条覆盖了精度、校准、算力和抗干扰，任何一条不过都得回头看设计。

## 当前实现架构（尚未实现）

### 简介

每颗 IMU 维护一份独立的状态，按 896.8Hz 逐样本积分陀螺，再用加速度和磁力计做低频校正。核心是 VQF 的三个机制：加速度在近惯性系滤波、零偏在线估计、磁干扰检测降权。

### 坐标系与四元数约定

世界系取 Z 轴竖直向上，与重力方向相反，右手系。

机体系沿用芯片原生轴，不做重映射。手背朝上、手指朝前平举时：x+ 指向肘部，y+ 指向身体右侧，z+ 指向天空。

三者构成右手系（x × y = z），与 datasheet 第 13 页的 Chip Orientation 一致。

选这套而不翻转，是因为 z+ 朝上正好与重力反方向一致。静止时加速度读数落在 +z，与世界系的 up 同向，滤波的初始条件天然成立，省掉一次轴变换。

代价是 x+ 指向肘部而不是指尖，读起来别扭，但不影响计算——相对姿态和弯曲角取的都是相对量。

U13 在 U14 右侧 10mm，即 U14 到 U13 的位移沿 +y。

十二颗 IMU 同型号同封装，板面朝向一致，所以共用同一套机体系定义，不做逐颗重映射。

四元数用 Hamilton 乘法，`q = [w, x, y, z]`，表示把机体系向量旋转到世界系。单位四元数，每步更新后归一化。

统一用 `float32`。S3 的单精度 FPU 直接支持，双精度会慢一个数量级，没有用到的理由。

### 双 IMU 融合

手背两颗刚性固定在板上，间距 10mm，方向沿 +y。同样的运动，两颗读到的东西只差力臂带来的那一点，其余完全一致。合起来用比单颗稳。

合的方式按逆方差加权：

```
ω = (ω13/σ13² + ω14/σ14²) / (1/σ13² + 1/σ14²)
```

`σ` 是各颗的噪声标准差，静态标定时测出来存 NVS。两颗同型号同批次时 `σ` 接近，权重就接近各半。

权重按方差倒数分配，是因为两个独立噪声源相加时这样得到的方差最小。这是标准结论，不需要额外调参。

收益有三条：

| 项 | 变化 |
|---|---|
| 白噪声 | 降 √2，约 29% |
| 零偏估计方差 | 降一半，长时间漂移更慢 |
| 单颗异常 | 被另一颗压住，不会直接把姿态带偏 |

融合后的陀螺和加速度喂给同一个 VQF 实例，不是两颗各跑一个再融合姿态。这样手掌只占一份解算开销，全系统 12 颗 IMU 只对应 11 个解算实例。

### 差分做一致性检查

差值本身不浪费，拿来判断两颗读数自不自洽：

```
a_dif = a13 - a14 - ω × (ω × r)
```

减掉向心项之后理论上应该接近零，剩下的只有角加速度项，量级很小。实测长时间偏离阈值，说明某颗出了问题，要么陀螺饱和，要么加速度计卡住。

发现不一致时把可疑那颗的权重压到 0.1，让另一颗顶上，同时记一条日志。压权重而不是直接剔除，是因为判断本身可能出错，留个尾巴比一刀切安全。

10mm 的力臂测角加速度信噪比只有 3 到 5 倍，不足以当主信号源，所以这里只做一致性检查，不拿差分单独解算姿态。

### 单颗 IMU 的更新流程

每个样本走一遍，顺序固定：

1. 陀螺积分：`q_gyr = q ⊗ exp(ω·dt/2)`，用一阶近似 `exp(θ) ≈ [1, θ/2]` 后归一化
2. 加速度转到世界系：`a_w = R(q_gyr) · a_body`
3. 在近惯性系低通：`a_w_filt += alpha · (a_w - a_w_filt)`，`alpha` 取 0.01
4. 转回机体系：`a_b_filt = R(q_gyr)ᵀ · a_w_filt`
5. 用 `a_b_filt` 与重力方向算倾角误差，转成小角度修正旋转 `δq`
6. `q = δq ⊗ q_gyr`，归一化

`dt` 不写死。它由 `sample` 层随批次给出，取批时间戳差除以本批样本数。ODR 由芯片内部振荡器决定，标称 896.8Hz 实际有千分之几的偏差，写死常数会让积分误差随时间累积。

第 3 步是 VQF 与普通互补滤波的分水岭。直接对机体系加速度低通，会把运动加速度也当成重力一起滤，导致倾角随动作偏。先转到世界系再滤，滤的是「世界系里看加速度的缓慢变化」，再转回来只取重力分量。

### 零偏估计

静止检测靠两个条件：角速度模长低于 0.05 rad/s，且加速度模长在 9.81 上下 0.3 m/s² 以内，连续保持 0.5 秒。

检测到静止时，零偏按一阶低通更新：`bias += 0.01 · (ω - bias)`。运动中也保持更新，但系数降到 0.0005，靠长时间的慢收敛补偿温漂。

零偏直接在上面积分的第 1 步里扣掉，不单独存修正项。

### 磁干扰检测

只对手掌姿态生效，磁力计 100Hz 更新。

维护一个磁场模长的慢速均值 `mag_ref` 和一个方向参考 `q_mag_ref`。每个新读数：

- 模长偏离 `mag_ref` 超过 30% → 标记干扰，磁权重置零，本次不校正航向
- 方向与参考夹角超过 15 度且持续 2 秒 → 认为环境磁场确实变了，重新学习参考
- 其余情况按正常权重校正航向

干扰状态下航向只靠陀螺维持，短时间内没问题，时间长了会漂。这是没有外部参考时的物理上限。

### 校准状态机

```
IDLE ──(静止 1s 自动)──► GYRO_BIAS ──► YAW_ZERO ──► RUNNING
                                                  │
        (首次使用或长按按键) ──► MAG_CALIB ────────┘
```

各状态做的事：

| 状态 | 动作 | 退出条件 |
|---|---|---|
| GYRO_BIAS | 累计静止样本求均值，写入零偏 | 采满 500 个样本 |
| MAG_CALIB | 采集多方向磁场，最小二乘拟合椭球 | 采满 200 个点或超时 30 秒 |
| YAW_ZERO | 记录当前航向为「正前方」 | 立即 |
| RUNNING | 正常解算 | 长按或重新戴上时退出 |

椭球拟合解 9 个系数，存 NVS。拟合用的是标准最小二乘，不需要迭代。

### 相对姿态

`fusion_process_batch` 结束后，用最新一轮的 12 个绝对四元数算相对量：

```
q_rel[i] = q_hand⁻¹ ⊗ q_finger[i]
```

手掌姿态取 U13 与 U14 的融合结果。两颗安装朝向相同，直接把四元数做球面插值取中点即可，比各算一个再平均省事。

相对四元数每帧重算一次，开销是 10 次四元数乘法，可以忽略。

### 算力与内存

| 项 | 估算 |
|---|---|
| 单颗单次更新 | 约 4400 周期 |
| 11 个实例乘 896.8Hz | 约 18% 单核 |
| 手背融合开销 | 每样本约 60 周期，合计不到 0.5% |
| 每颗状态 | 约 120 字节 |
| 12 颗加缓冲 | 小于 4KB |

4400 周期来自 STM32F411 上的实测值，Xtensa LX7 的指令效率不同，实际数字以板上测量为准。第一版实现完成后先测一次 `esp_timer` 打点，偏差超过 50% 就回头优化。
